# Windows client working rules

- This is the selected **Familiar** native WinUI approach. Keep exploration controls and sample tasks out of production.
- `Tasks.Core` owns protocol/authentication, in-memory task state, and focus ordering. `Tasks.App` owns WinUI controls and Windows session protection. Never persist task payloads or ordering.
- Read `../../contracts/auth-and-updates.md` and `README.md` before changing authentication/storage. Use one protected endpoint/account/session envelope, not separately committed secrets and preferences. No password storage, certificate bypass, credential redirects, or raw exception logging.
- Strict vertical RED/GREEN tests for every behavior slice. Run core/storage C# tests and `node --test ../../tests/windows/*.test.mjs`.
- Linux compilation is only a C# gate: `dotnet build Tasks.App/Tasks.App.csproj -c Release -p:OutputType=Library -p:WindowsAppSDKSelfContained=false -p:PrepareForRunDependsOn=CopyFilesToOutputDirectory`. Never apply those overrides to Windows releases.
- Native builds retain self-contained deployment and merged WinUI PRI generation. `build.ps1` requires Windows and checks actual output inventory. Native launch/XAML, data protection, rendering, and installation are separate acceptance gates.
- Installer packaging uses `scripts/build-windows-installer.ps1 -BuildNumber N -AllowUnsigned`, pinned Velopack 1.2.161, and `installer/Tasks.iss` solely as an unregistered transition guard. Preserve the old Inno AppId for detection: refuse existing legacy installations and require one manual uninstall, never silently install side-by-side. Velopack owns the new `TasksWindows` registration and `current` layout under the per-user root. Uninstall must not delete the separately protected session directory. Require genuine full package/feed and real self-contained x64 files/merged PRI, never Linux compile-only output. Publish guarded setup aliases, not a raw setup that bypasses legacy detection.
- The combined release job requires selected Android/Windows jobs to succeed and accepts intentional unchanged-platform skips. Compare inputs against verified platform publication baselines; preserve unchanged outputs. Windows-only releases remain stable `vN` releases with `latest=false` so Android's Latest remains APK-compatible. The old Windows checker also uses Latest, so its legacy filename alias does not imply automatic discovery of Windows-only releases. Installer upload is gated on the real, isolated hosted-Windows install/render/close/uninstall script; diagnostics stay separate from release files. No personal-machine install/profile cleanup is authorized by a test command.
- Windows updates use Music's explicit Check → Download with progress → Restart and install system, never the Android manifest or a browser-only substitute. Page anonymous GitHub releases, select the highest matching stable `vN` Windows feed/full package, validate repository/package/version/channel, reject downgrades and fail closed on ambiguous/truncated metadata. Run the Velopack hook before WinUI with automatic startup apply disabled. Block restart during edits/mutations or failed protected-session verification; never persist tasks for updating. Run `Tasks.Update.Tests` in addition to Core/Storage tests. No commit, push, publication, installation, or live-account/database modification without authorization.
